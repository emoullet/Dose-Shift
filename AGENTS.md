# AGENTS.md

Repository-wide instructions for Codex and other coding agents working on Dose-Shift.

## Language

- Everything committed to this repository must be written in English.
- This includes documentation, file names, directory names, identifiers, variable names, function names, class names, comments, tests, fixtures, commit messages, issue/PR text generated by agents, and user-facing strings unless localization is explicitly introduced later.
- Do not introduce French text into repository artifacts unless explicitly requested for a localization resource.

## Product scope

Dose-Shift is a personal research and tracking application for an A-B-A medication-timing protocol involving antimuscarinic treatment, cognitive/vigilance measurements, bladder tracking, and confounder tracking.

The application must support data collection and analysis without autonomously recommending medication changes.

## Medical-safety boundary

- Do not generate or encode autonomous treatment recommendations.
- Do not silently change medication doses, schedules, protocol phases, thresholds, or clinical interpretations.
- Treat `docs/PROTOCOL.md` as a controlled product requirement. Any behavior that would alter the protocol must be explicitly requested.
- Preserve warnings and stop conditions from the protocol in relevant UX flows.

## Engineering principles

- Prefer simple, explicit, maintainable solutions over premature abstraction.
- Keep domain logic separate from UI code.
- Use strict typing wherever the selected language/toolchain supports it.
- Validate persisted and imported data at runtime.
- Keep all user data exportable in documented, non-proprietary formats.
- Avoid cloud dependencies for the initial product unless explicitly approved.
- Design mobile-first, while keeping desktop use comfortable.
- Preserve offline usability for core tracking flows.
- Do not add telemetry, analytics, or third-party tracking without explicit approval.

## Data integrity

- Store timestamps with timezone information or with enough metadata to reconstruct local time reliably.
- Never overwrite recorded measurements silently.
- Prefer append-only event records plus explicit edits/audit metadata where practical.
- Version exported data formats.
- Imports must fail safely and report validation errors clearly.

## Testing

- Add tests for domain logic and data migrations.
- Add regression tests when fixing bugs.
- Run relevant tests before considering a task complete.
- Do not weaken tests merely to make a change pass.

## Git workflow

- Work on focused feature branches.
- Keep commits small and coherent.
- Do not rewrite shared history unless explicitly requested.
- Do not include unrelated changes in a commit.

## Documentation

When introducing a meaningful architectural, product, or data-model decision, update `docs/DECISIONS.md` and any affected specification document.
